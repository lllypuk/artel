# Artel: выбор направления обзора команды

Статус: владелец выбрал **canon** — привычный desktop dashboard, вариант 4. Первый экран — обзор всей команды. Это выбор направления и композиции, не разрешение реализации. PRODUCT.md фиксирует подтверждённые факты. Изменений приложения/API и пользовательской установки здесь нет.

## Что исправляем

Свежий offscreen рендер production QML на fictional HTTP fixture, 2026-11-18: три почти равнозначные колонки; нерегулярный ритм; большие недоступные кнопки между основными данными; технические даты и история конкурируют с содержанием; наблюдатели вынесены в диагностический drawer. Исторические PNG сверены со свежим рендером. Это ручная native-дизайн оценка, без web DOM detector и без доступа к owner data.

## Пользовательская задача

После открытия понять, какие подключённые участники наблюдаются, к каким проектам они привязаны, что Pi сообщает об активности, где свежих данных нет. Затем открыть наблюдателя/заявленную терминальную сессию или перейти к ручным задачам проекта. Не показывать фиктивных поручений, согласований, графиков прогресса, затрат и скорости работы.

Видимая единица — существующая observer registration и её текущая binding, а не каждая runtime. Кандидаты и старые инкарнации отделены. Неподключённую логическую команду Artel пока не знает; обещание «вся команда» означает все подключённые наблюдения с честным empty state для ещё не подключённых.

## Семь исходных направлений

В порядке близости рабочей ситуации, до выбора направления:

1. Каталог студийной команды: прохладный светлый текст на глубоких зелёно-серых поверхностях, компактный системный sans, имя и состояние читаются прежде служебных параметров. Подпись — одинаково выровненные status rails у каждой карточки.
2. Система указателей общественной библиотеки: индиго, белый и медный, ясные разделы и короткие строки; простое различение разделов и активного выбора.
3. Музейный указатель залов: нейтральный угольный, приглушённый кирпичный и светлый текст, свободный ритм подписей; проектные группы без изменения native navigation.
4. Программа ансамбля: чернильно-синий shell, светлый текст и приглушённый коралловый акцент, системный sans с табличными цифрами; индивидуальные участники образуют общий состав. Подпись — общий выровненный столбец состояния при смене состава фильтром.
5. Промышленный каталог образцов: тёмная олива, серебристый текст и охра, плотные однообразные карточки; материал переносит только шкалу плотности и различение семейств.
6. Указатели транспортного атласа: холодные синие поверхности, белый текст и тёплые метки, отчётливая связка проект/наблюдатель без рисования ложных маршрутов сообщений.
7. Научная постерная сессия: холодные нейтрали, сливовый и мятный, ясные подписи и секции, работа с длинными названиями без декоративных метрик.

У всех направлений стандартные desktop navigation, filters, list/card selection и detail pane. Культурный источник даёт только шрифт, палитру, плотность и один приём. Не делать приложение афишей, расписанием, терминалом или печатным каталогом.

## Выданные альтернативы и оценка

Impeccable direction seed: `seed:bd140fb4412749ed`, mode Operate; назначено исходное направление 4. Это не пользовательский выбор.

- Variable font specimen — declined: огромные буквы и осевые регуляторы не улучшают узнаваемость участников или ясность данных. Берём дисциплину типографической иерархии, не форму specimen.
- Dark developer console — competitive: знакомая среда и высокая плотность выигрывают по быстроте сканирования, но тотальная моноширинность и множество панелей менее понятны для обзора людей/проектов. Альтернатива сохраняет native controls, без terminal/cockpit costume.
- Airport yellow wayfinding — declined: сильное выделение потери связи полезно, но доминирующий жёлтый не улучшает рабочее чтение команды. Берём дисциплину одного главного сигнала, не жёлтые вывески.
- Labanotation — declined: направление времени и символические дорожки не соответствуют latest-state без истории. Берём строгую общую ось выравнивания, не нотные/временные дорожки.
- Botanical folio — declined: lifecycle-стадии и botanical imagery создают ложную семантику развития задач. Берём одинаковый масштаб всех участников, не растительные формы.
- Airline wallet — declined: билеты/штампы создают ложные стадии handoff. Берём изоляцию необратимых действий от навигации, не купоны или tear-off.

Назначенное направление 4 усилено: единая типографическая шкала (specimen), одно заметное предупреждение потери связи (wayfinding), строгая ось состояний (labanotation), одинаковый вес участников (folio), revoke/prune только в раскрытых деталях с подтверждением (wallet). Исходное направление 1 показывается как авторская рекомендация; dark developer console — полноценная альтернатива. Стандартный desktop dashboard остаётся отдельным тихим выходом.

## Выбор владельца

В ответ на сравнение владелец явно выбрал `canon`: нейтральный привычный desktop dashboard, без переноса образов ансамбля, студии или терминала. База — `.impeccable/mocks/decision/canon.html` и его статический рендер. Нативные стандартные действия, ясная иерархия, список всей подключённой команды, фильтр по проекту, детальная область выбранного наблюдателя. Три предыдущих варианта не смешивать с выбранным по инициативе исполнителя. Следующее уточнение — приложения-ориентиры уровня исполнения, затем brief/план реализации; технические права/гейты не расширены. Автоматически открытый выбор закрыт по просьбе владельца, новых окон не открывать без запроса.

## Неизменяемые границы

- Работающий API/данные владельца не трогать. Макеты используют только явно обозначенные fictional data.
- Idle не означает done; stale не означает stopped; candidate не означает team assignment.
- Сохранить manual CRUD, очереди/историю, CAS/idempotency, draft/unknown-outcome protection, отдельные owner и observer channels.
- Без установки шрифтов/пакетов, глобальных настроек, реальной интеграции новых агентов и новых backend capabilities.
- Сначала выбор композиции и понятный brief; DESIGN.md и исполняемый ralphex plan не подменяют этот выбор.
