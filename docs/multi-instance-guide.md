# Запуск нескольких инстансов agent-shatrov (multi-agent режим)

Один и тот же бинарник `agent-shatrov` может работать одновременно под разными
«должностями»: аналитик, разработчик, тестировщик и т.д. Каждый инстанс имеет
свой конфиг, свой токен бота Mattermost и свой системный промпт.

## Что нужно для подъёма второго/третьего инстанса

1. **Отдельный бот в Mattermost** — создай в системе интеграций столько ботов,
   сколько ролей нужно. У каждого должен быть свой `token` и `bot_username`.
2. **Отдельный YAML-конфиг** — скопируй пример из `docs/roles/<role>.yaml`,
   замени токены и пути к БД/логам, чтобы инстансы не конфликтовали.
3. **Общий канал/DM в Mattermost** — боты должны видеть друг друга и общий
   канал, в котором будут координироваться.
4. **Белый список `mattermost.team_bots`** — каждый бот должен знать username
   соседей из команды. Сообщения от ботов вне этого списка игнорируются.

## Конфигурация роли

```yaml
transport:
  type: mattermost

mattermost:
  server_url: "https://mattermost.example.com"
  token: "<токен-этого-бота>"
  bot_username: "analyst-bot"
  owner_user_id: "<user-id-владельца>"
  team_bots:
    - "developer-bot"
    - "tester-bot"

role:
  name: "analyst"
  system_prompt: |
    Ты — аналитик команды. Твоя задача — исследовать задачи, собирать
    требования и давать чёткие рекомендации. Отвечай кратко.
```

`role.system_prompt` переопределяет встроенный системный промпт именно для
этого инстанса. Если не задан — используется стандартный персональный ассистент.

## Запуск

```bash
# Первый инстанс
./bin/agent config-analyst.yaml

# Второй инстанс (в другом терминале / systemd unit / Docker container)
./bin/agent config-developer.yaml
```

Каждый инстанс читает свой конфиг, пишет в свою БД (`database.path`) и
подключается к Mattermost под своим пользователем.

## Предохранители петель

При multi-agent запуске обязательно настройте `safeguards` одинаково или
синхронно между инстансами:

```yaml
safeguards:
  loop_warn_bot_messages: 10      # предупреждение в лог после 10 бот-сообщений
  loop_suppress_bot_messages: 15  # остановить автоответы после 15 бот-сообщений
  max_replies_per_minute: 5       # не более 5 ответов/мин на один тред
```

Счётчики идут внутри одного инстанса, но все роли используют одну логику:
- собственные сообщения (`sender_id == self_bot_id`) игнорируются;
- лимит сбрасывается при появлении сообщения человека-владельца;
- при превышении suppress-лимита агент пишет в тред призыв к человеку.

## Telegram vs Mattermost

- В режиме `telegram` роли не имеют смысла — там один агент на одного
  человека-владельца. Поле `role` всё равно можно задать для логов/статуса.
- В режиме `mattermost` обязательно: разные `token`, `bot_username`, `database.path`
  и `logging.file`. Иначе инстансы будут конфликтовать за одну БД/лог.

## Проверка

1. @-mention аналитика в канале — он должен ответить.
2. Попросите аналитика позвать разработчика: `@developer-bot посмотри`.
3. Убедитесь, что разработчик отреагировал, а не игнорирует сообщение
   (проверьте `team_bots`).
4. Спровоцируйте длинный бот-в-бот диалог — предохранитель должен остановить
   петлю примерно на 15 сообщениях ботов и эскалировать человеку.
