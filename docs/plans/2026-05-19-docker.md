# Docker: контейнеризация агента

**Дата:** 2026-05-19  
**Цель:** Запускать агента в Docker-контейнере без CGO-зависимостей, для будущего предоставления сервиса не-ИТ пользователям.

## Итоговая архитектура

- SQLite-драйвер: `modernc.org/sqlite` (pure Go, без CGO)
- Docker-образ: multi-stage `golang:1.26-alpine` → `alpine:3.21`, ~15–20 MB
- Конфиг: `config.yaml` монтируется как read-only volume `/app/config.yaml`
- Данные: Docker named volume `agent_data` → `/app/data/`
- Секреты: env vars переопределяют значения из config.yaml

### D-3: Создать Dockerfile

- [ ] Complete

**Файл:** `Dockerfile` (корень репозитория)

```dockerfile
# Stage 1: build
FROM golang:1.26-alpine AS builder
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN go build -o /app/agent ./cmd/agent

# Stage 2: runtime
FROM alpine:3.21
RUN apk add --no-cache ca-certificates tzdata
WORKDIR /app
COPY --from=builder /app/agent .
VOLUME ["/app/data"]
ENTRYPOINT ["/app/agent", "-config", "/app/config.yaml"]
```

Обратить внимание:
- `ca-certificates` нужен для HTTPS к Telegram API и LLM
- `tzdata` нужен для `proactive.timezone` (Europe/Moscow и т.д.)
- data/ объявлена как VOLUME, но используется named volume из Compose

### D-4: Создать docker-compose.yml

- [ ] Complete

**Файл:** `docker-compose.yml` (корень репозитория)

```yaml
services:
  agent:
    build: .
    image: agent-shatrov:latest
    volumes:
      - ./config.yaml:/app/config.yaml:ro
      - agent_data:/app/data
    restart: unless-stopped
    # Опционально: переопределить секреты через env vars
    # environment:
    #   - TELEGRAM_TOKEN=your_token
    #   - LLM_API_KEY=your_key

volumes:
  agent_data:
```

## Что НЕ входит в этот план

- Миграция данных из существующей БД — данные начинаются с нуля
- Multi-tenant поддержка (несколько пользователей в одном контейнере)
- Auto-provisioning инфраструктуры — отдельный будущий проект
- Helm charts / Kubernetes — выходит за рамки
